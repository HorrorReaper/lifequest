### 2. Supabase redirect URL allowlist

`Authentication → URL Configuration → Redirect URLs` must include `<origin>/auth/callback`. Without it Supabase ignores `redirectTo` and sends recovery links to the site URL, so password reset links go nowhere. This is the most common cause of broken reset links.

### 3. Email delivery decision

Password reset uses Supabase's built-in mailer: free, but heavily rate-limited and not intended for production. Moving to custom SMTP is a cost decision and was deliberately left untouched.

## Known risks carried forward

- **The tool system is proven by one example.** The claim that a new tool costs one component plus one registry line holds for Vision, which is the simplest shape (a singleton with history). It is not yet proven against a bounded run such as the time audit, which is the shape most likely to expose a missing abstraction. See [Self-improvement tools](../features/tools.md).
- **`20260805184127_add_tool_exercise_type.sql` carries full copies of two functions.** plpgsql has no partial replace, so `learning_replace_catalog` and `submit_learning_exercise` were reproduced in full (extracted mechanically from the original migration, not retyped, with only the marked edits). Future changes to either must target this newer copy. The migration has not been executed against a database, so the SQL is unverified beyond review.
- **`src/lib/gamification.ts` still duplicates the level/XP math** that `src/lib/city/city.ts` owns. The city refactor removed one duplicate (`src/lib/city.ts`) but deliberately left this one: unifying it touches XP display across dashboard, city, and onboarding.
- **`mobile-journal-wizard.tsx` validates insight types against a hand-maintained Set** that TypeScript does not check. Adding a sixth insight type without updating it will silently discard entire drafts on restore, not just the mark. Documented in [Journal and insights](../features/journal.md).
- **Two parallel lesson systems** remain (`src/lib/lessons.ts` and `src/lib/learning-paths.ts`), alongside `/dashboard` and `/dashboard2`.
